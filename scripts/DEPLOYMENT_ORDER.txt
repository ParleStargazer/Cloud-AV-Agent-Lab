Cloud AV Agent Lab deployment order
===================================

Recommended order for a clean Windows Lighthouse instance:

1. Create or update the dedicated test administrator account
   Run from an elevated PowerShell:

     .\scripts\create-administrator-user.ps1 -Password "<password>"

   The default account name is AvTester-Admin. Use -Username only if you need a
   different dedicated test administrator account.

2. Install AutoLogon and configure test administrator auto-login
   Run from an elevated PowerShell:

     .\scripts\setup-administrator-autologon.ps1

   The script opens Sysinternals AutoLogon. Enter the AvTester-Admin account
   and password manually. Do not store the password in this repository.

3. Create the Cloud AV Agent Lab workspace
   Run on the cloud VM from an elevated PowerShell:

     .\scripts\setup-cloud-av-workspace.ps1

   This creates:

     C:\CloudAvAgentLab\
       bin\
       cases\
       StartAgent.ps1
       StartDesktopWorker.ps1
       README_WORKSPACE.txt

4. Build the unified agent suite locally
   Run from the project checkout in the conda environment:

     .\scripts\build-agent-suite.ps1

   The build output is:

     scripts\pack\dist\agent-suite\bin\
       guest-agent.exe
       desktop-worker.exe
       _internal\

5. Deploy the unified agent suite to the cloud VM
   Copy every file under:

     scripts\pack\dist\agent-suite\bin\

   into:

     C:\CloudAvAgentLab\bin\

6. Configure required Windows environment variables on the cloud VM
   Recommended for this project stage: edit the generated startup scripts on
   the VM and configure VM-local environment variables there.

   In StartAgent.ps1, configure all four tokens:

     CLOUD_AV_GUEST_AGENT_TOKEN
     CLOUD_AV_GUEST_AGENT_UPLOAD_TOKEN
     CLOUD_AV_GUEST_AGENT_EXECUTION_TOKEN
     CLOUD_AV_DESKTOP_WORKER_TOKEN

   In StartDesktopWorker.ps1, configure the same worker token:

     CLOUD_AV_DESKTOP_WORKER_TOKEN

     C:\CloudAvAgentLab\StartAgent.ps1
     C:\CloudAvAgentLab\StartDesktopWorker.ps1

   You may also use machine-level environment variables if preferred. Do not
   copy real tokens back into the repository, logs, reports, or evidence.

7. Create scheduled tasks
   Run from an elevated PowerShell on the cloud VM:

     .\scripts\create-guest-agent-task.ps1
     .\scripts\create-desktop-worker-task.ps1

   Guest Agent runs StartAgent.ps1 as SYSTEM at startup. Desktop Worker runs
   StartDesktopWorker.ps1 when the AvTester-Admin account logs on and stays
   bound to localhost.

   StartAgent.ps1 enables controlled execution actions by default. If a
   diagnostic run must start the agent without execution actions, create the
   task with:

     .\scripts\create-guest-agent-task.ps1 -DisableExecutionActions

8. Reboot and verify
   After reboot, confirm:

     - Guest Agent is listening on the configured external port.
     - Desktop Worker is listening only on 127.0.0.1:8001.
     - Guest Agent /worker/status reports AvTester-Admin and ready=true.
